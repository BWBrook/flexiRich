## Sequence and reporting horizon

1. Preserve Goal008 code, documents and recoverable final evidence in Git;
   restore the project R library to the existing lockfile.
2. Verify the joint/sequential identity calculation with a tiny finite-grid
   example. Reuse the existing full-candidate baseline without a detected-only
   selection correction or another class-contrast prior.
3. Freeze and run first-year posterior predictive checks on deep-server. Keep
   observed effort, species identities and all 50 candidates. Compare the
   existing primary and wider-tail prior profiles as sensitivity, not a contest
   to select the narrowest richness interval.
4. Interpret the ecological failures before choosing one modification. Freeze
   forecasts for occasions 53–153 before any further detection outcomes are
   exposed. Use subsequent simulations to diagnose mechanisms and richness
   recovery, rather than requiring a broad synthetic screen before forecasting.
5. Establish Huon Ridge's reviewed pool and deployment metadata before deciding
   external calibration and layered assessment. Continue manuscript development
   through local makedoc as scientific results become available.

The immediate reporting point follows the repository's remote-run rule: tested,
committed code and input/run contract, a verified persistent remote launch, and
exact monitoring commands. Do not poll until a long run finishes. A scientifically
poor baseline is an informative outcome, not a reason to retune the evidence.
